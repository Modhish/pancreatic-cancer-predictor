# Бизнес-логика системы

## Назначение

DiagnoAI Pancreas в текущем виде является исследовательским веб-прототипом для оценки риска по показателям ОАК/СОЭ. Он не ставит диагноз, не подтверждает рак поджелудочной железы и не заменяет врача. Логика системы построена как инженерный конвейер: ввести данные, проверить их, получить оценку риска моделью, объяснить факторы и сохранить результат.

## Основной сценарий

1. Пользователь регистрируется или входит в систему. Пароль сохраняется только в виде хеша, а дальнейшие запросы выполняются с bearer-токеном.
2. Пользователь выбирает роль и язык интерфейса. Основной язык проекта для защиты - русский.
3. Пользователь вводит 18 лабораторных показателей: `wbc`, `rbc`, `plt`, `hgb`, `hct`, `mpv`, `pdw`, `neut_abs`, `neut_pct`, `lymph_abs`, `lymph_pct`, `mono_abs`, `mono_pct`, `eos_abs`, `eos_pct`, `baso_abs`, `baso_pct`, `esr`.
4. Backend приводит значения к числам и проверяет допустимые диапазоны. Если значение нечисловое или выходит за допустимые границы, API возвращает ошибку валидации.
5. Random Forest Classifier рассчитывает вероятность принадлежности к группе повышенного риска. Порог классификации равен `0.3`, он выбран на валидационной выборке.
6. Модуль SHAP/объяснений формирует список факторов, которые сильнее всего повлияли на оценку риска. Эти факторы показываются в карточках и на диаграммах.
7. LLM получает уже готовый результат модели: класс, вероятность, SHAP-факторы и выбранные лабораторные значения. LLM не делает предсказание и не может изменить результат модели.
8. Если LLM недоступна, генерирует нечитабельный русский текст или использует опасные медицинские формулировки, backend возвращает безопасный шаблонный комментарий.
9. Результат сохраняется в SQLite: вероятность, уровень риска, SHAP-факторы, комментарий, введенные значения, роль и язык. Audit log хранит событие и технические поля, но не полные медицинские данные.
10. Пользователь видит результат в интерфейсе, может переключать аудиторию комментария и скачать PDF-отчет.

## Роль SHAP-диаграмм

SHAP-графики объясняют вклад признаков в оценку модели. Они не являются отдельным медицинским тестом и не доказывают причинную связь. Под каждой визуализацией смысл такой: положительный вклад повышает расчетный риск модели, отрицательный вклад снижает его, а итоговая вероятность остается результатом Random Forest, а не мнением LLM.

## Роль LLM

LLM используется только как модуль пояснения. Она переводит модельный результат в понятный комментарий для пациента, врача или исследователя. Prompt прямо ограничивает роль LLM: это screening/risk-support aid, а не диагноз; LLM не должна писать, что у пациента рак, назначать лечение или менять вероятность.

## Выходные данные

Система возвращает:

- `prediction`: бинарный класс после применения порога.
- `probability`: вероятность положительного класса.
- `risk_level`: Low, Moderate или High.
- `shap_values`: список факторов и их вкладов.
- `metrics`: воспроизводимые метрики модели из JSON-артефакта.
- `ai_explanation`: пояснение LLM или безопасный шаблон.
- `patient_values`: нормализованные введенные показатели.

## Ограничения бизнес-логики

Система не учитывает анамнез, симптомы, визуализацию, CA 19-9, гистологию и осмотр врача. Поэтому вывод является только оценкой риска по ограниченному набору лабораторных признаков и должен использоваться как учебный прототип поддержки решений.
